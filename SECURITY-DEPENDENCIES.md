# Dependency security maintenance (2026-10-23)

Use Node 24.22.1 and `npm ci --ignore-scripts --no-audit --no-fund`. Nest common/core/platform/testing move together from 9 to corrected 11.2.7, with CLI 11.0.24, schematics 11.1.0 and mapped-types 2.1.1 (its declared peers support Nest 10/11). The maintained platform parent supplies Multer 2.4.0 and Express 5.2.1. This avoids forcing a new Multer major into Nest 9. TypeScript 5.9, compatible TypeScript ESLint 8 and Prettier 3 follow the updated tooling peers. Application routes, controllers, service payloads and database schema remain unchanged.

The old Supertest 6.3.4 parent is explicitly deprecated in its current npm metadata, which recommends maintained 7.1.3+. The dev-only 7.2.2 parent and compatible types therefore replace that unsupported line; the existing e2e import uses the supported default API.

Prisma/client stay on matching 4.16.2 rather than introducing an unrelated database client major. Run `node scripts/generate-client-offline.cjs` before `npm run build`. The generation helper copies only the public schema to an isolated temporary project, supplies an unused synthetic database URL and writes the generated client into node_modules. A generation-only preload rejects environment-file reads before opening them. It does not bootstrap the Nest application, migrate, seed or connect to SQLite. The existing tracked environment file was identified by filename only and was not read or changed by this task.

The Python API uses Python 3.11.17 and uv 0.13.5: `cd tracking_energy_api && uv sync --frozen`. The supported Python minor is explicitly 3.11 while original NumPy 1.24.2 is retained; numerical algorithms and data are unchanged. Flask 3.1.3, Werkzeug 3.1.9, Flask-CORS 6.0.5 and Flask-PyMongo 3.0.1 resolve together with PyMongo 4.19.0. The former UTF-16 requirements file is now a UTF-8 hashed export of the same uv.lock, retaining a portable pip consumption path without a second unlocked graph.

Selected contracts use the actual Nest testing module/controllers with service values replaced before instantiation, and actual Flask asynchronous routes with Mongo/configuration/calculator modules replaced before application import. They deny network connections and never import AppModule, run the seeder, call a real provider or execute main.ts. The Flask tests preserve request conversions, response shapes and existing CORS behavior; they do not redefine authorization or numerical behavior.

New pull-request CI runs frozen installs, safe Prisma generation and a build in draft. Ready adds only the selected contracts, filtered by source paths. It uses read-only permissions, bounded workers and PR-specific cancellation. No local server, Docker, complete application suite, business data operation or deployment is part of this verification. Fresh exact-package public OSV comparisons are recorded separately; known uncorrected parent constraints and no-fix advisories must remain explicit rather than claiming a globally clean graph.
